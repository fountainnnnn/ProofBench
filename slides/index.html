It reads the docs so you do not have to.

Give the orchestrator agent a plain-language brief: 'benchmark invoice-extraction tools', or any other category. It searches Google and scrapes documentation and pricing pages with Oxylabs, then proposes an editable spec: candidates, dataset, metrics. You confirm, it runs.

Proposed spec

tesseract easyocr paddleocr doubleword + discovered tools
Dataset: data/demo, 15 labelled invoices
Metrics: exact accuracy, field F1, CER, latency, cost
Demo category: invoice extraction
Run benchmark

Integrations written from each tool's own documentation.

Doubleword reads the scraped docs and generates the full adapter: install commands, API calls, and output mapping to one shared contract. The sandbox builds and validates it; a failed build goes back for regeneration.

The same Doubleword deployment is also the batch inference layer: every LLM request in a run, from adapter codegen to the hosted extraction candidates, goes out as a batched request through Doubleword.

Every candidate races in its own Daytona sandbox.

A pre-warmed pool builds, validates, and runs candidates in parallel. A failed build triggers self-repair: the agent reads the error, patches the adapter, retries. Every line streams to the console.

Scored by code, never judged by a model.
